## 一、玩家在服务端的化身:`msgagent`

每个成功登录的玩家,在服务端都对应一个**独立的 `msgagent` 服务**(actor),它就是玩家在服务端的化身。

- 由游戏服 `gated` 在玩家登录时通过 `skynet.newservice "msgagent"` 创建(`examples/login/msgagent.lua:24`)。
- 一个玩家一个 agent,彼此隔离,互不阻塞。
- agent 持有玩家会话状态:`gate`(所属游戏服)、`userid`、`subid`(`examples/login/agent.lua:14`)。
- agent 负责处理该玩家的全部业务请求(示例里是 echo + 业务逻辑)。
- 玩家下线时 agent 调 `skynet.exit()` 自我销毁(`examples/login/agent.lua:27`)。

> 注意:示例里有两个 agent 文件。`msgagent.lua` 是游戏服里管理玩家会话的服务;`agent.lua` 是玩家业务化身。msgserver 框架下,真正承载玩家业务的是 `agent.lua` 启动的服务,由 `gated` 内部转发驱动。

### 涉及的服务角色

| 服务 | 文件 | 角色 |
|---|---|---|
| `main` | `examples/login/main.lua` | 启动入口,拉起 logind 和 gated |
| `logind` | `examples/login/logind.lua` | **登录服务器**:鉴权、账号密码校验、防重复登录 |
| `gated` | `examples/login/gated.lua` | **游戏服网关**:分配 subid、管理玩家会话、转发业务请求 |
| `msgagent` / `agent` | `examples/login/agent.lua` | **玩家化身**:每玩家一个,处理业务 |
| `loginserver` 库 | `lualib/snax/loginserver.lua` | 登录鉴权协议(DH 交换 + HMAC + DES) |
| `msgserver` 库 | `lualib/snax/msgserver.lua` | 游戏服会话协议(握手 + 防重放 + 断线重连) |

## 二、整体架构

```
                    ┌─────────────┐
   ①登录鉴权        │   logind    │  登录服务器 (port 8001)
 client ──────────► │ (loginserver)│  DH交换/HMAC/DES + 账号校验
                    └──────┬──────┘
                           │ ③login(uid,secret) 注册到游戏服
                           ▼
                    ┌─────────────┐
   ②游戏服握手      │    gated    │  游戏服网关 (port 8888)
 client ──────────► │ (msgserver) │  HMAC握手 + 业务转发
                    └──────┬──────┘
                           │ ④每玩家创建
                           ▼
                    ┌─────────────┐
                    │  msgagent   │  玩家化身 (一玩家一个)
                    │   (agent)   │  处理业务请求
                    └─────────────┘
```

登录分**两个连接、两个阶段**:

- **阶段 A — 登录鉴权**:连 `logind`(8001),协商密钥、验账号,拿到 `subid`,然后断开。
- **阶段 B — 接入游戏服**:连 `gated`(8888),用 secret 做 HMAC 握手,之后正常收发业务。

## 三、阶段 A:登录鉴权(连接 logind,端口 8001)

基于行文本协议(`\n` 分隔)。代码见 `lualib/snax/loginserver.lua` 注释与 `launch_slave`。

| 步 | 方向 | 内容 |
|---|---|---|
| 1 | S → C | `base64(8字节随机 challenge)` |
| 2 | C → S | `base64(8字节客户端 DH key)` |
| 3 | S | 生成 8 字节服务端 DH key |
| 4 | S → C | `base64(DH-Exchange(server key))` |
| 5 | S/C | 双方各自算出共享密钥 `secret = DH-Secret(...)` |
| 6 | C → S | `base64(HMAC(challenge, secret))` —— 证明持有 secret |
| 7 | C → S | `DES(secret, base64(token))`,token = `base64(user)@base64(server):base64(password)` |
| 8 | S | `auth_handler(token)` 解出 user/server,校验密码 |
| 9 | S | `login_handler(server, uid, secret)` → 分配 `subid` |
| 10 | S → C | `200 base64(subid)` |

### 关键代码

- **密钥协商 + HMAC 挑战**:`loginserver.lua:55-73`
- **token 解密 + 鉴权**:`loginserver.lua:77-79` → `logind.lua:auth_handler` (16 行),校验 `password == "password"`
- **登录处理 + 防重复登录**:`logind.lua:login_handler` (26 行)
  - 查 `server_list` 找到目标游戏服(`gated`)
  - 若已在线先 `kick` 旧会话(`multilogin = false`)
  - 调 `skynet.call(gameserver, "lua", "login", uid, secret)` 让游戏服分配 subid
  - 记录 `user_online[uid]`
- **错误码**:`401` 鉴权失败 / `403` login_handler 失败 / `406` 重复登录

### 主从结构(loginserver)

`logind` 内部是 1 master + N slave(`loginserver.lua:launch_master`,默认 8 个):

- **master**:监听 8001,接受连接后轮询分发给 slave,执行 `login_handler`、写最终响应。
- **slave**:并发处理单个连接的 DH 握手与 token 解密(CPU 密集的加密操作分摊到多个服务)。

## 四、阶段 B:接入游戏服(连接 gated,端口 8888)

拿到 `subid` 后,客户端**断开 logind**,连游戏服 `gated`。改用**二进制长度前缀包协议**(大端,2 字节包头)。代码见 `lualib/snax/msgserver.lua`。

### 1. 握手包(第一个包)

```
base64(uid)@base64(server)#base64(subid):index:base64(hmac)
```

- `index`:连接序号,**单调递增**,防重放。
- `hmac = HMAC(secret, "username:index")`,secret 来自阶段 A 的密钥协商。

服务端 `do_auth`(`msgserver.lua:173`)校验:

| 检查 | 失败码 |
|---|---|
| username 是否已登录(`user_online`) | `404 User Not Found` |
| `index > 上次 version`(防重放) | `403 Index Expired` |
| HMAC 是否匹配 | `401 Unauthorized` |
| 解析异常 | `400 Bad Request` |
| 全部通过 | `200 OK` |

校验通过后绑定 `connection[fd] = u`,更新 `version = index`,记录 fd/ip。

### 2. 业务请求/响应

握手成功后进入请求循环(`msgserver.lua:do_request`):

```
请求 (C→S): [2字节size][content][4字节session]
响应 (S→C): [2字节size][content][1字节ok][4字节session]
```

- 每个请求带递增 `session`,服务端按 session 缓存响应(`u.response`)。
- 业务通过 `request_handler` 转发给玩家的 `agent`:
  `gated.lua:77` → `skynet.rawcall(u.agent, "client", msg)`
- agent 处理后返回结果(`agent.lua:48` 的 `client` 协议 dispatch)。

### 3. 断线重连(msgserver 的核心价值)

这正是 `login/client.lua` 演示的场景:

- **断线不立即销毁 agent**:连接断开触发 `disconnect_handler` → agent 进入 `afk` 状态(`agent.lua:36`),会话保留。
- **重连用更大的 index**:客户端用 `index+1` 重新握手,旧 index 失效(403),防止重放攻击。
- **session 级幂等**:服务端缓存每个 session 的响应。重连后:
  - 复用旧 session(同 version)→ 视为冲突/重复,可安全丢弃。
  - 新 session → 正常处理。
  - 已发过的响应可重发,保证"恰好一次"语义。

代码:`msgserver.lua:do_request` 243-297 行(session 缓存、版本比对、重发逻辑)。

## 六、关键安全设计小结

| 机制 | 作用 | 位置 |
|---|---|---|
| DH 密钥交换 | 协商不经明文传输的共享 secret | `loginserver.lua:64-66` |
| HMAC 挑战 | 证明客户端持有 secret,防伪造 | `loginserver.lua:69` |
| DES 加密 token | 账号密码不明文上线 | `loginserver.lua:77` |
| index 单调递增 | 握手防重放 | `msgserver.lua:182` |
| session 响应缓存 | 断线重连幂等,"恰好一次" | `msgserver.lua:243-297` |
| socket 8K 限流 | 防恶意大包攻击 | `loginserver.lua:53` |
| 防重复登录 | 同账号挤掉旧会话 | `logind.lua:31-36` |

## 七、如何运行

```bash
# 终端 1:启动登录 + 游戏服
./skynet examples/config.login

# 终端 2:启动客户端跑登录鉴权流程
./3rd/lua/lua examples/login/client.lua
```

客户端会依次完成:DH 握手 → token 鉴权(拿 subid)→ 连游戏服握手 → 收发业务 → 演示断线重连。

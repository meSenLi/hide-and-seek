# 新增系统开发指南

本说明面向开发者，解释如何在 `agent_layered` 框架中新增一个系统模块，包含数据声明、持久化、RPC 注册和生命周期管理。

## 1. 新系统位置与注册

- 新系统文件一般放在 `script/service/agent_layered/systems/`。
- 文件名与系统模块名一致，例如 `script/service/agent_layered/systems/achievement.lua`。
- 系统模块需要在 `script/service/agent_layered/agent_boot.lua` 的 `agent.systems` 中注册，才能被会话加载、初始化和保存。

示例注册：

```lua
local system_achievement = require "agent_layered.systems.achievement"

local function init_systems()
    agent.systems.core = system_core
    agent.systems.inventory = system_inventory
    agent.systems.achievement = system_achievement
    ...
end
```

## 2. 系统基类和基础结构

所有系统建议继承 `agent_layered.systems.base`。

```lua
local base = require "agent_layered.systems.base"
local achievement = base.new {
    unlocked = {},
    points = 0,

    __fields__ = {
        unlocked = { persist = true, sync = true },
        points = { persist = true, sync = true },
    },
}

```

- `base.new(t)` 会创建一个继承自基类的系统对象。
- RPC 使用 `rpc_*` 命名方法（如 `rpc_add_point`），`session` 自动收集。
- `__fields__` 用于控制哪些字段参与持久化和同步。

## 3. 数据声明和字段元信息

`__fields__` 是显式的字段元信息表，只有在这里声明的字段才会被持久化。

字段元信息支持两种写法：

- 布尔值：`true` 等价于 `{ persist = true, sync = true }`
- 表：`{ persist = bool, sync = bool }`

默认行为是：`persist = false, sync = false`。

常见用法：

```lua
__fields__ = {
    items = { persist = true, sync = true },
    gold = { persist = true, sync = false },
    cache = false,
}
```

解释：

- `persist = true`：系统字段会被保存到持久化存储。
- `sync = true`：系统字段可公开同步给客户端或外部查询。
- 未声明或显式 `false`：不会自动持久化。

## 4. 持久化与加载

基类提供默认 `save()` / `load(state)` 实现：

- `save()` 会收集 `__fields__` 中 `persist = true` 的字段并返回数据表。
- `load(state)` 会从存储恢复这些字段。

如果系统需要自定义保存逻辑，可以覆盖 `save()`。一般情况下只需在 `__fields__` 中声明字段即可。

## 5. RPC 增加方式

### 1. 在 game.sproto 中定义协议

```
-- config/proto/game.sproto
mypackage 7 {
    request {
        name 0 : string      -- 必填字段
        count 1 : integer    -- 必填字段
    }
    response {
        ok 0 : integer
    }
}
```
sproto 自动校验类型，非法请求在解码阶段被拒绝。

### 2. 系统 RPC 只能使用 `rpc_*` 命名方法。

```lua
function achievement:rpc_add_point(args)
    self.points = self.points + (args.amount or 1)
    return { points = self.points }
end
```

- 基类会自动扫描对象中以 `rpc_` 开头的方法，并去掉前缀作为 RPC 名称。
- 例如 `rpc_add_point` 会映射成 `add_point` RPC。
- 你必须在 `config/proto/game.sproto` 中为该 RPC 定义对应 `request` 和 `response`。

RPC 方法应返回一个结果表，通信层会把它作为响应返回给客户端。
## 6. 生命周期方法

建议实现以下生命周期钩子：

- `function sys:init(agent, state)`
  - 必须调用基类初始化：`self.super.init(self, agent, state)` 或 `base.init(self, agent, state)`。
  - 绑定 `self.agent`、`self.log`、计时器等基础功能。

- `function sys:load(state)`
  - 若需要自定义字段恢复，可以覆盖该方法。
  - 基类默认会恢复 `__fields__` 中声明的字段。

- `function sys:save()`
  - 若默认逻辑不满足，可覆盖该方法返回自定义持久化数据。

- `function sys:init_finish()`
  - 可选。所有系统 `init()` 完成后，`agent_boot` 会调用该钩子。

- `function sys:shutdown()`
  - 清理计时器、取消订阅、释放引用。
  - 最后调用基类：`self.super.shutdown(self)` 或 `base.shutdown(self)`。

## 7. 事件与日志

系统可使用 `agent.events` 订阅和发布事件：

```lua
self.agent.events:subscribe("EVENT_LOGIN", callback)
self.agent.events:publish("EVENT_LOGIN", self.agent.uid)
```

日志工具可通过 `self.log` 使用：

```lua
self.log:info("achievement loaded for %s", self.agent.uid)
self.log:error("failed to grant reward")
```

## 8. 示例系统模板

```lua
local base = require "agent_layered.systems.base"
local achievement = base.new {
    unlocked = {},
    points = 0,

    __fields__ = {
        unlocked = { persist = true, sync = true },
        points = { persist = true, sync = true },
    },
}

function achievement:rpc_add_point(args)
    self.points = self.points + (args.amount or 1)
    return { points = self.points }
end

function achievement:rpc_get_status(args)
    return {
        unlocked = self.unlocked,
        points = self.points,
    }
end

function achievement:init(agent, state)
    self.super.init(self, agent, state)
end

function achievement:shutdown()
    self.super.shutdown(self)
end

return achievement
```

## 9. 注意事项

- 新系统添加后，必须在 `agent_boot.lua` 注册到 `agent.systems`，否则不会被初始化和持久化。
- `__fields__` 只控制基类自动持久化，必要时可手动覆盖 `save()` / `load()`。
- RPC 名称推荐使用小写、简洁、语义明确的方式。
- 如果系统需要跨系统通信，优先考虑事件订阅而不是直接访问其他系统内部字段。
